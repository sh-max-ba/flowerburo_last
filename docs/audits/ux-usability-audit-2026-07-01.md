## 1. Вердикт

Отдельные экраны сделаны хорошо (касса — 2 клика до продажи, канбан сделок с автосохранением, крупные тач-кнопки флориста), но система страдает не от плохих экранов, а от **плохой их сборки в единое целое**. Все 4 боли — проявления одной корневой проблемы: **нет единой модели «объекта» и «действия»**. Один заказ живёт в 3 пунктах меню, «принять деньги» разбито на 3 экрана, «возврат» — это 3 разных слова в 3 местах, склад раздут в ERP из 7 пунктов сайдбара.

Самое болезненное и притом дешёвое: **флорист у кассы физически не может оформить ни один возврат**, а возврат прямой продажи с прилавка **невозможен вообще ниоткуда** — нет ни кнопки, ни серверного экшена.

Хорошая новость: серверная логика возвратов **заказов** уже готова (`cancelOrder` умеет возвращать выданные заказы, гейтится через `runCashAction`) — не хватает только UI-точек входа. Для **возврата прямой продажи** нужен новый экшен `reverseSale` — единственная операция без домена. Большинство исправлений — фронт и перекомпоновка навигации.

## 2. Боль №1 — «слишком много пунктов меню»

**Что не так**
- Меню владельца — **19 пунктов в 5 группах** (`src/lib/nav.ts:45`). Половину занимает группа «Склад» — **7 пунктов первого уровня** (`src/lib/nav.ts:71`, `54-62`). Ежедневно нужен 1-2.
- **Менеджер не видит ни одного складского пункта** — все складские `roles:["owner"]` (`src/lib/nav.ts:54-61`), хотя приёмку и списание в магазине часто делает именно он.
- **Две «Истории»** с одинаковой иконкой `history` (`src/lib/nav.ts:60-61`) — визуально неотличимы.
- **Дубли входов**: «Поставщики» — и пункт меню, и первая вкладка «Настроек» (`src/lib/nav.ts:59`, `src/components/settings/settings-page.tsx:135`). «Черновики» — и пункт, и кнопка-бейдж на Столе (`src/lib/nav.ts:52`, `src/components/orders/orders-page.tsx:155`).
- **Группа «Обзор» из одного пункта** «Дашборд» — лишний разделитель (`src/lib/nav.ts:68`).
- **«Партии» висят пунктом даже при выключенном учёте по партиям** — скрывать по `getTrackLotsEnabled` (`src/lib/nav.ts`).
- **Флорист — обратная крайность**: 1 пункт «Стол заказов», «Касса» появляется только при открытой ночной смене — сайдбар выглядит поломанным (`src/lib/nav.ts:116`).

**Решения**
| Решение | Эффорт |
|---|---|
| Свернуть 7 складских пунктов в ОДИН «Склад» с внутренними вкладками (таб-бар по pathname). −6 пунктов (`src/lib/nav.ts:71`) | L |
| Объединить «Историю кассы» и «Историю склада» в один пункт «История» с вкладками (`src/lib/nav.ts:60-61`) | M |
| Скрывать пункт «Партии» по `getTrackLotsEnabled` (не ждать перекомпоновки) (`src/lib/nav.ts`) | S |
| Не рендерить `SidebarGroupLabel` для групп из 1 пункта; «Дашборд» — вверх без заголовка (`src/lib/nav.ts:68`) | S |
| Убрать дубль «Поставщики» из настроек, `defaultValue="orders"` (`src/components/settings/settings-page.tsx:135`) | S |

## 3. Боль №2 — «операции разбросаны по разным местам»

**Что не так**
- **Нет глобального «+ Создать» / командной палитры**. Топбар — только звук + статус смены (`src/components/app-topbar.tsx:48-89`). Любая операция начинается с квеста по 18-пунктовому сайдбару.
- **Один заказ проходит 3 пункта меню**: черновик на кассе → `/orders/drafts` → `/orders` → `/ready-orders` (`src/lib/nav.ts:70`). После «Букет готов» карточка молча исчезает со Стола (`src/components/orders/orders-page.tsx:64`).
- **«Принять деньги» — 3 экрана, 3 экшена**: продажа `createSale` на `/cash`, предоплата `acceptDealPayment` в сделке, доплата `completePickupOrder`/`handOrderToCourier` на `/ready-orders` (`src/components/orders/ready-orders-page.tsx:208`). Клиент подходит доплатить — операция спрятана в «Готовых заказах».
- **Создание заказа — 4 экшена, 3 экрана** (`createOrder`/`createOrderDraft`/`createOrderFromDeal`/`finalizeOrderDraft`) с разными формами (`src/app/actions.ts:1050`, `src/components/deals/deal-detail-page.tsx:844`).
- **Ввод клиента и товаров дублируется в 3 местах** (сделка/касса/стол), данные из сделки на кассу не подтягиваются (`src/components/cash/cash-page.tsx:236`, `src/components/deals/deal-detail-page.tsx:1182`). Дублирование `createCustomer`/`createCashCustomer`.
- **Склад: списание запускается из двух мест по-разному** — акт `stock_out` vs `writeOffLot`.
- **Управление сменой разорвано**: открыть/закрыть — в топбаре, внести/изъять — вглубине `/cash` → «Касса за смену», а `/shifts` кассовых операций не запускает (`src/components/shifts/shift-pages.tsx:164`).
- **Создание акта склада** доступно только с экрана «Склад»; «Акты» лишь ссылаются назад на `/stock?new=...` (`src/app/stock/acts/page.tsx:94`).

**Решения**
| Решение | Эффорт |
|---|---|
| Кнопка «+ Создать» в топбаре, **фильтруемая по роли** (флористу — только Продажа) (`src/components/app-topbar.tsx:48`) | M |
| Объединить orders/drafts/ready-orders в одну «Доску заказов» с вкладками-статусами и счётчиками (`src/lib/nav.ts:51-53`) | L |
| «Принять оплату» на `/ready-orders` и в карточке сделки; в «Касса за смену» — лента «ожидают доплаты» (`src/components/orders/ready-orders-page.tsx:208`) | M |
| Общий компонент «строка заказа/продажи» + «Продать на кассе» из карточки клиента и сделки (`src/components/cash/cash-page.tsx:236`) | L |
| Продублировать «Внести/Изъять наличные» на `/shifts/[id]` открытой смены (`src/components/shifts/shift-pages.tsx:164`) | M |
| Диалог создания акта — переиспользуемым, чтобы открывался прямо на `/stock/acts` (`src/app/stock/acts/page.tsx:94`) | M |

## 4. Боль №3 — «сложно оформить возврат»

Самая острая: для части операций возврат не «сложно», а **невозможен**.

**Что не так**
- **Флорист у кассы не может оформить НИ ОДИН возврат**: `/history` отдаёт `AccessDenied` всем кроме owner/manager (`src/app/history/page.tsx:14`), а на `/cash` и `/ready-orders` кнопок возврата нет. Каждый возврат = «позовите владельца».
- **Возврат прямой продажи невозможен вообще ниоткуда**: в `actions.ts` нет экшена сторно `createSale`, в списке чеков смены нет кнопки (`src/app/actions.ts:996`, `src/components/cash/shift-receipts-list.tsx:13`). Данные `cash_refund` с `sale_id` существуют (`src/components/cash/shift-cash-timeline.tsx:251`), но точки входа нет.
- **Нет единого понятия «Возврат»** — три слова: «Отменить заказ», «Сторнировать», «Отменить операцию» (`src/components/history/cash-ledger.tsx:310`, `374`, `430`). Персонал ищет «вернуть деньги за товар» и не находит.
- **Одно действие — два разных заголовка диалога**: `cancelOrderAction` из `orders-page.tsx:218` и `cash-ledger.tsx:289` с разными текстами.
- **Возврат готового/выданного заказа спрятан в истории кассы**: на `/ready-orders` только «Выдать»/«Передать курьеру» (`src/components/orders/ready-orders-page.tsx:352-408`); отменить — лишь через `/history` → раскрыть строку. Домен `cancelOrder` это умеет (`src/lib/db/domain/order-lifecycle.ts:1096`).
- **Диалог отмены на `/orders` умалчивает про деньги** и обещает откат склада, которого для готового заказа нет (`src/components/orders/orders-page.tsx:411`).
- **Частичный возврат невозможен нигде** — только весь чек/заказ целиком (`src/lib/db/queries/cash.ts:451`).
- **Тихая блокировка при закрытой смене** — кнопка активна, операция падает невнятным тостом (`src/lib/db/domain/order-lifecycle.ts:1000`, `src/app/actions.ts:1108`).

**Решения**
| Решение | Эффорт |
|---|---|
| Экшен `reverseSale`/`refundSale` (по образцу `reverseCashTransactionAction`) + кнопка «Вернуть» на чек продажи — закрывает единственную операцию БЕЗ входа (`src/app/actions.ts:996`) | M |
| Дать флористу доступ к возврату своей продажи текущей смены (оговорка: `canUseCash` = только ночная смена) (`src/app/history/page.tsx:14`, `src/components/cash/shift-receipts-list.tsx:13`) | M |
| «Оформить возврат» в карточке заказа на `/ready-orders` для статусов Готов/Выдан/Курьер → тот же `cancelOrder` (`src/components/orders/ready-orders-page.tsx:404`) | M |
| Условный текст диалога отмены по статусу + сумма возврата в кнопке; единый заголовок (`src/components/orders/orders-page.tsx:406`, `411`) | S |
| Дизейблить возврат при закрытой смене с подсказкой «Откройте смену» вместо тихого падения (`src/lib/db/domain/order-lifecycle.ts:1000`) | S |
| Единый мастер «Возврат» на кассе. MVP = сумма целиком, без разбора позиций. Способ возврата **зеркалит способ оплаты** (метод-парность уже есть в `refundOrderPayments`) (`src/components/history/cash-ledger.tsx:310`) | L |

## 5. Боль №4 — «черновики работают странно»

**Что не так**
- **Создание и просмотр в разных местах**: черновик создаётся только в модалке «Создать заказ» на кассе (`src/components/cash/cash-page.tsx:1675`), после сохранения модалка закрывается без перехода/ссылки — заказ «пропал» (`src/components/cash/cash-page.tsx:262`). Флорист вообще не видит `/orders/drafts` (`src/lib/nav.ts:52`).
- **«Предоплата-намерение» проводится позже и в чужую смену**: деньги взяты при создании, но в кассе их нет до «Отправить в работу», а тогда они садятся в **сегодняшнюю** смену (`src/lib/db/domain/order-lifecycle.ts:615`). Прямой источник расхождений кассы.
- **Термин перегружен**: раздел «Черновики» (`status='Черновик'`) vs внутренний `orderDraft` в карточке сделки — это форма, а не сохраняемый черновик (`src/components/deals/deal-detail-page.tsx:188`).
- **Редактор даёт меньше контроля, чем создание**: в `OrderEditSheet` у черновика нельзя менять скидку на чек (`src/components/orders/order-edit-sheet.tsx:106`), а подзаголовок «Склад спишется при отметке Букет готов» для черновика неверен (`src/components/orders/order-edit-sheet.tsx:163`).
- **Отправка в работу совмещает 3 решения в один клик**: валидация состава, требование смены, выбор «оставить/обновить цены» без пояснения (`src/components/orders/drafts-page.tsx:199`, `246`).
- **Валюта на карточке черновика — `₽`, а не `сом`**: `drafts-page.tsx:140` определяет локальный `money()` с `₽`, игнорируя общий `formatMoney()` из `src/lib/utils.ts:8` (везде «сом»). Единственное место с рублём во всём UI. (найдено при сверке; в отчёт агентов не попало)

**Решения**
| Решение | Эффорт |
|---|---|
| Убрать «Черновики» из меню → вкладка на Столе (owner/manager; синхр. 3 места: navItems, canAccessSection, roles); в тосте после сохранения — ссылка «Открыть черновик» (`src/lib/nav.ts:52`, `src/components/cash/cash-page.tsx:262`) | M |
| В модалке заменить «Предоплата» явным выбором: «Деньги уже получены» vs «Только записать намерение»; на карточке — бейдж «Предоплата НЕ принята» (`src/lib/db/domain/order-lifecycle.ts:615`) | M |
| Добавить «Скидка на чек» в `OrderEditSheet` для черновика + корректный подзаголовок (`src/components/orders/order-edit-sheet.tsx:106`, `163`) | S |
| Заменить локальный `₽`-форматтер на общий `formatMoney` (`src/components/orders/drafts-page.tsx:140`) | S |
| В диалоге выбора цены — пояснение к каждой кнопке; блокировку по смене — с кнопкой «Открыть смену» (`src/components/orders/drafts-page.tsx:199`) | S |
| Развести словарь: блок в сделке назвать «Оформить заказ», а не «черновик» (`src/components/deals/deal-detail-page.tsx:188`) | M |

## 6. Целевое меню (ДО → ПОСЛЕ)

**ДО — 19 пунктов, 5 групп (владелец):**
```
Обзор:             Дашборд
CRM:               Сделки · Клиенты · Букеты
Работа:            Касса · Стол заказов · Черновики · Готовые заказы · История кассы
Склад:             Склад · Остатки · Акты · Партии · Инвентаризация · Поставщики · История склада
Администрирование: Смены · Настройки · Пользователи
```

**ПОСЛЕ — владелец, ~10 пунктов:**
```
Дашборд                          (без метки группы, сверху)
Касса                            (+ топбар «+ Создать»)
Заказы   ▸ Черновики · Новые · В работе · Готовы · Завершённые (счётчики)
CRM      ▸ Сделки · Клиенты · Букеты
Склад    ▸ Товары · Остатки · Акты · Партии* · Инвентаризация · Поставщики · История
           (+ единое «＋ Операция»: Приход · Списание · Инвентаризация · Импорт)
История  ▸ Касса · Склад(owner)
Смены · Настройки · Пользователи
```
`*` «Партии» — только при включённом `getTrackLotsEnabled`.

**ПОСЛЕ — менеджер:** Касса · Заказы · CRM · Склад(если открыть) · История(Касса). Нет: Дашборд, Пользователи, Настройки.

**ПОСЛЕ — флорист:** не сайдбар из 1 пункта, а осмысленный минимум — крупные плитки «Стол заказов» и «Касса» (Касса задизейблена с подсказкой «Откройте смену», а не исчезает). Проверить доступ к каталогу букетов-шаблонов для сверки состава.

Ключевые слияния: Заказы (−2), Склад (−6), История (−1), убрать дубль «Поставщики» и группу «Обзор».
